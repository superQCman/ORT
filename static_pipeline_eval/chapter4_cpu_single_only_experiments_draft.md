# 第四章 CPU 实验与结果分析

## 4.1 实验设置

本章围绕 ORT 上的 DLRM CPU 推理过程展开实验，目标是验证第三章提出的两级建模思路是否能够在真实推理负载上成立：第一步预测单算子时延，第二步利用静态流水线模型将节点级预测聚合为整图时延。与只关注单节点回归不同，本章更关心两个问题：其一，静态特征能否稳定刻画算子级执行代价；其二，在 branch-parallel 执行存在显著并行重叠的前提下，节点级预测能否进一步恢复整图关键路径。

### 4.1.1 实验平台

实验平台为 Kunpeng-920 服务器。虽然整机提供更大的计算资源，但本文统一采用单 NUMA 执行域，以避免跨 NUMA 干扰带来的额外不确定性。对应执行域包含 24 个物理核心、24 MiB 共享 L3 以及 4 个 DDR4-2933 内存通道。实验过程中固定 `intra-op` 与 `inter-op` 线程配置，并保持 ORT 推理图、线程绑定方式和采样流程一致，从而保证不同样本之间的可比性。

### 4.1.2 数据集与标注方式

实验数据来自 ORT 导出的 DLRM ONNX 图及其配套的 `op_shapes`、算子 profiling 和整图时间线。单算子数据共包含 195,900 条样本，覆盖 9 类实验场景。这些实验场景对应不同的 Embedding 表配置、Top MLP 规模以及 Bottom MLP 规模。数据集中进一步包含 3,265 个 `combo` 配置，其中每个 `combo` 对应一组输入规模参数，即一个 batch size 与每次 lookup 索引数的组合。相关参数范围如表 4-1 所示。按照算子机理可将样本划分为五类：计算主导类、索引访存类、布局搬移类、轻计算-访存混合类以及视图/元数据类，具体组成见表 4-2。

表 4-1 单算子数据集中的主要配置参数范围

| 参数 | 含义 | 取值范围 |
| --- | --- | --- |
| 实验场景 | 对应不同的 Embedding 表配置、Top MLP 规模和 Bottom MLP 规模 | 共 9 类 |
| `combo` 配置 | 由 batch size 与每次 lookup 索引数组合确定的输入规模配置 | 共 3,265 组 |
| batch size | 单次推理中的样本数 | `1024-2048` |
| 每次 lookup 的索引数 | 单次 embedding lookup 的索引数量 | `1000-2000` |
| `intra-op` 线程数 | 单个算子内部并行线程数 | `1-5` |
| `inter-op` 线程数 | 算子间并行线程数 | `1, 3, 4, 5, 6` |

单算子标签取自 ORT profiling 中的算子级时延。为减弱冷启动扰动，每个样本均丢弃最早的一个 profile batch，再对剩余 batch 的同名节点求均值，得到 `label_operator_actual_dur_us`。整图真值采用与之对应的时间线 span，同样丢弃首个 batch 后求均值。这样处理的目的，是尽可能使单算子标签与整图标签遵循一致的统计口径。

### 4.1.3 数据划分与评价指标

为避免同一组合配置同时出现在训练集与测试集，本文按 `sample_group=combo` 做 `7:2:1` 划分，实际样本数为 train/val/test = `137,160 / 38,880 / 19,860`。此外，本文额外构造两类外推测试：一类保留 batch size `1856|1920|1984|2016|2048` 作为未见 shape 配置，另一类仅保留 `num_threads=3` 作为未见线程数配置，用于观察模型跨配置泛化能力。

单算子层面采用 `MAE`、`MAPE`、`RMSE` 与 `R^2` 评价精度；整图层面除 `MAE`、`MAPE` 外，还统计 `P50/P90` 相对误差，以衡量误差尾部的稳定性。需要说明的是，整图预测面对的是显著并行重叠的 branch-parallel 执行，因此如果仅简单累加节点时延，往往会系统性高估整图 makespan；这一点将在 4.4 节通过消融实验进一步验证。

## 4.2 单算子性能建模结果

本节首先给出 single-only 设置下的总体单算子精度，然后从类别差异、典型算子行为以及跨配置泛化三个角度分析其有效性。由于这一版实验不再引入 grouped MLP，对比对象仅保留纯解析基线与统一 single MLP，从而使本章的证据链更集中于“解析代理 + 统一学习器 + 静态聚合”这一主线。

### 4.2.1 总体预测精度

表 4-3 给出了纯解析模型与统一 single MLP 的总体结果。纯解析模型并不直接对全部测试样本做统一估计，而是在每个算子组内选择最合适的 active analytical proxy；按这一口径统计，在 13,902 条可覆盖测试样本上得到 `MAPE = 0.2364`，覆盖率为 70.0%。之所以不能覆盖全部测试样本，是因为 `view/meta` 这类算子缺少足够稳定的 active analytical feature，如果强行纳入总体比例误差，反而会不真实地放大解析基线的误差。

与解析基线相比，统一 single MLP 在完整测试集上的 `MAPE` 为 0.0759，`R^2` 为 0.9854，表明在共享 30 维特征池的条件下，模型能够较稳定地恢复节点时延的主导趋势。图 4-3 中多数样本分布在 `y=x` 参考线附近，进一步表明该模型可以作为整图聚合的有效输入。由此可见，本节实验的重点并不在于追求接近零误差的单算子预测，而在于验证静态特征是否能够将节点级误差控制在整图建模可接受的范围内。

### 4.2.2 分类别误差分析

表 4-4 与图 4-4 进一步展示了五类算子的误差差异。其中，`view/meta` 与 `layout move` 两类算子最容易预测，其 `MAPE` 分别为 0.0535 和 0.0645；`Gather` 的 `MAPE` 为 0.0743；`light compute-mem` 与 `compute dominant` 的误差相对更高，分别为 0.0972 和 0.1087。该结果与第三章给出的机理分析一致。

一方面，视图/元数据算子和布局搬移算子的执行路径相对稳定，性能主要由张量形状和数据搬移规模决定，因此更容易被静态特征捕获。另一方面，`Gather` 依赖随机访存，`ReduceSum`、`Relu` 等混合类算子同时受到线程调度与访存行为影响，而 `Gemm/MatMul` 在小维度条件下又存在微核利用率不足的问题，这些因素都会增加误差离散度。因此，类别差异不宜视为实验噪声，而应理解为 ORT CPU kernel 执行机理在误差分布上的具体体现。

### 4.2.3 典型算子现象分析

图 4-5 至图 4-8 给出了几类代表性算子的预测行为。`Gather` 的尾部误差相对突出，反映出大表随机访问带来的内存时延波动；`ReduceSum` 的误差会随归约规模增大而逐步收敛，说明解析代理对归约工作量的刻画是有效的；`Transpose` 与 `Concat` 的误差主要与数据搬移规模相关；`Gemm/MatMul` 则在小规模 `M/N/K` 区域出现更显著偏差，表明此时硬件尚未进入稳定饱和状态。

上述现象表明，模型误差并非完全无结构的黑盒偏差，而是能够被硬件与 kernel 行为解释的残差。这一点比单纯报告总体 `MAPE` 更具分析价值，因为它说明第三章提出的特征设计具有明确物理含义，而非依赖偶然的数据相关性。

### 4.2.4 跨配置泛化能力

图 4-9 和图 4-10 展示了两类外推测试结果。对于未见 batch size，模型的 `MAPE` 为 0.0689；对于未见线程数，`MAPE` 为 0.0773。两者都与随机测试集上的 0.0759 处于同一数量级，未出现显著退化，表明当前特征集合并未过度依赖某一组固定配置。

相较之下，未见线程数的误差略高于未见 shape。这是因为线程数变化不仅影响理论并行度，还会影响任务切分粒度、同步开销与缓存竞争，因此其外推难度本身更高。尽管如此，当前结果仍表明统一 single MLP 在第四章所关注的配置空间内具有可接受的泛化能力，因而本章无须再引入额外模型分支来支撑主要结论。

## 4.3 整图静态聚合结果

单算子精度只是第一步。对 DLRM 这类 branch-parallel 推理图而言，真正困难的问题在于：在多个 embedding 分支、bottom 与 tail 相互重叠的条件下，如何由节点级预测恢复整图关键路径。本节验证第三章 3.3 中提出的静态流水线聚合模型是否能够完成这一任务。

### 4.3.1 整体整图精度

表 4-5 给出了整图预测的总体结果。在 331 个完整图配置上，静态流水线模型的 `MAPE` 为 0.0647，`R^2` 为 0.9931，`P50/P90` 相对误差分别为 0.0509 和 0.1261。该结果表明，节点级误差并未在整图聚合中被放大到不可接受的程度；同时，静态聚合模型不仅能够给出接近真实值的整图 makespan，还能够较稳定地控制误差尾部。图 4-11 中大部分测试点紧贴参考线分布，也进一步支持了这一判断。因此，第三章提出的“先节点、后整图”的两级建模路径，在本组 single-only 实验中得到了实验支持。

### 4.3.2 不同 batch size 下的稳定性

图 4-12 按 batch size 给出了整图误差分布。整体来看，各个 batch size 上的 `MAPE` 大致落在 `0.03-0.10` 区间内，没有出现随 batch 增长而持续恶化的趋势。即便在误差相对较高的 `batch_size=1440` 处，其 `MAPE` 也约为 0.1000，仍处于可接受范围。

这一结果表明，静态流水线模型并非仅在局部规模上有效，而是能够在不同工作集大小下保持较平滑的误差曲线。考虑到 DLRM 中 embedding lookup、分支归约和 top MLP 的张量规模都会随 batch size 改变，这种稳定性是方法成立的重要前提。

### 4.3.3 不同并行度下的趋势恢复能力

图 4-13 进一步给出了不同 `inter_threads` 条件下的整图预测结果。当 `inter_threads=1` 时，模型 `MAPE` 约为 0.0392；在 `inter_threads=3/4/5/6` 时，`MAPE` 分别为 0.0851、0.0774、0.0781 和 0.0680。虽然误差会随并行度变化产生一定波动，但整体上模型能够正确恢复“并行度增加后时延下降、收益逐步递减”的趋势。

据此可见，第三章中用于描述 branch 槽位竞争的静态近似是有效的。该近似并不旨在完全替代真实运行时调度，而在于捕获整图性能的主导结构；从本节结果看，这一目标已经得到实现。

### 4.3.4 典型时间线与关键路径分析

图 4-14 与图 4-15 给出了典型配置下的真实时间线、预测时间线及关键路径分解。结果显示，模型不仅能够预测整图 span，还能在较大程度上恢复 bottom、embedding branch 与 tail 之间的先后关系。少数偏差主要集中在 barrier 附近以及同步敏感节点上，表明剩余误差更多来自运行时同步与局部波动，而非整图结构本身的错误刻画。

这类案例分析的价值在于，它能够从结构层面解释整图误差的来源。相较于仅报告散点图或平均误差，关键路径重放更有助于说明模型产生有效预测的原因，并界定当前尚未覆盖的误差来源。

## 4.4 消融实验与剩余误差分析

为了验证本章结论所依赖的关键设计，本文仅保留四个最具解释力的变体：`Analytical + simple add`、`Analytical + pipeline`、`Analytical + single MLP + simple add` 和 `Analytical + single MLP + pipeline`。本文不再引入额外模型分支，因为它们对于当前 single-only 证据链并非必要，且可能削弱论述重点。因此，本节关注的核心问题并非不同模型之间的局部优劣，而是“单算子学习器”和“静态流水线聚合”是否分别构成不可替代的组成部分。

### 4.4.1 关键组件的作用

表 4-6 以及图 4-16 至图 4-18 给出了明确的消融结果。对于纯解析模型，如果整图仅做 simple add，则 `MAPE` 高达 2.0450；当聚合方式改为 pipeline 后，`MAPE` 降至 0.1389。对于引入统一 single MLP 的版本，如果仍采用 simple add，整图 `MAPE` 为 1.8814；而切换到 pipeline 后，`MAPE` 进一步下降到 0.0647。

这组结果表明，整图预测精度的决定性改进并非主要来自单点回归精度的边际提升，而是来自对并行重叠与同步边界的显式建模。在这一实验设置下，simple add 更适合作为负对照，因为它忽略了 branch-parallel 执行中的重叠关系，因此会系统性高估 makespan。基于这一点，pipeline 所带来的数量级改进具有明确的方法学依据，而不应视为偶然波动。

同时，对比 `Analytical + pipeline` 的 0.1389 和 `Analytical + single MLP + pipeline` 的 0.0647 可知，更准确的单算子预测仍然是必要条件。第四章的结论并非“仅依赖 pipeline 即可获得高精度整图预测”，而是“节点级学习器负责降低局部偏差，静态流水线负责将节点级预测组织为符合执行结构的整图估计”，两者缺一不可。

### 4.4.2 剩余误差的来源

表 4-7 与图 4-19 汇总了当前模型仍然较难处理的几类样本。第一类是大表随机访存 `Gather`，其误差来源于内存访问时延的天然波动；第二类是极小张量的视图/元数据算子，此时框架调度与 bookkeeping 开销占比较高，使得时延对形状特征更加敏感；第三类是小维度 `Gemm/MatMul`，在低利用率条件下其真实执行代价偏离了饱和计算近似；第四类是同步敏感的整图配置，局部偏差会在 tail barrier 处被放大。

这些残差有一个共同点：它们都对应 ORT CPU 执行过程中较难被纯静态信息完全恢复的动态效应。因此，本章实验既证明了所提方法的有效性，也清楚界定了它的边界条件。对于论文写作而言，保留这部分分析是必要的，因为它表明本文并未夸大方法能力，而是明确指出了误差仍然集中的场景。

## 4.5 本章小结

本章在 195,900 条单算子样本和 331 个完整图配置上验证了第三章提出的两级建模框架。实验结果表明：统一 single MLP 在单算子测试集上的 `MAPE` 为 0.0759，显著优于纯解析基线的 0.2364；在未见 batch size 与未见线程数配置上，模型 `MAPE` 分别为 0.0689 和 0.0773，说明其具备较稳定的跨配置泛化能力；进一步将节点级预测接入静态流水线后，整图预测 `MAPE` 达到 0.0647，`P90` 相对误差为 0.1261，说明节点误差并未在整图层面失控放大。

消融实验进一步明确了本章结论所依赖的核心因素。若忽略并行重叠，仅做 simple add，则整图误差显著增大；只有当节点级学习器与静态流水线聚合同步存在时，整图精度才达到可接受水平。因此，第四章的主要证据并不在于某个单独模型在局部指标上的偶然领先，而在于完整方法链条在单算子、外推测试和整图预测三个层面上均呈现出一致结论。该结果足以支撑第三章提出的方法设计，并为第五章的进一步讨论提供可靠实验基础。
