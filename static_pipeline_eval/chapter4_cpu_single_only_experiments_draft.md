# 第四章 CPU 实验与结果分析

## 4.1 实验设置

本章围绕 ORT 上的 DLRM CPU 推理过程展开实验，目标是检验第三章提出的两级建模路线在真实负载上是否成立：首先用静态特征预测单算子时延，再用静态流水线模型将节点级预测聚合为整图时延。围绕这一目标，实验重点回答两个问题：其一，单算子模型在随机测试集上是否足够准确，能够作为整图预测的稳定输入；其二，在 branch-parallel 存在显著并行重叠的条件下，静态聚合是否仍能恢复整图关键路径与总体时延。图 4-1 给出了单算子数据采集与建模流程，图 4-2 给出了由节点级预测进一步恢复整图时间线与关键路径的静态聚合流程。为避免正文在每次重跑实验后被自动覆盖，`chapter4_cpu_single_only_experiments_draft.md` 固定保留为稳定正文与复现说明；每次运行同步得到的最新数值草稿统一写入 `ORT/static_pipeline_eval/chapter4_cpu_single_only_experiments_data_sync.md`。

### 4.1.1 实验平台

实验平台为 Kunpeng-920 服务器。虽然整机可提供更大的总资源，但本文统一在单 NUMA 执行域内完成建模与评估，以避免跨 NUMA 访存和调度干扰掩盖方法本身的效果。对应执行域包含 24 个物理核心、24 MiB 共享 L3 以及 4 个 DDR4-2933 内存通道。实验过程中固定 `intra-op` 与 `inter-op` 线程配置，并保持 ORT 推理图、线程绑定方式和采样流程一致，从而使不同样本之间具有可比性。

### 4.1.2 复现信息

为保证后续复现实验与本文统计口径一致，本文固定如下运行条件。

- ORT 版本：`ONNX Runtime CANN 1.23.2`，运行环境为 `ort` conda 环境。
- 操作系统环境：`Huawei Cloud EulerOS 2.0 (aarch64)`。
- Turbo / 频率漂移控制：当前 `run_ort_sweep_extensible_no_trace.sh`、相关 artifact 清单和硬件 profile 中未记录显式关闭 Turbo、锁定 governor 或关闭频率漂移的额外系统操作；本文仅按 Kunpeng-920 的 `2.6GHz` 基频口径报告平台参数，复现实验应保持相同宿主机与负载隔离条件。
- 线程亲和性策略：runner 默认启用 `numactl --cpunodebind="$NUMA_NODE" --membind="$NUMA_NODE"` 的单 NUMA CPU/内存绑定；在 `run_ort_sweep_extensible_no_trace.sh` 中默认 `NUMA_NODE=1`，同时固定 `intra-op` 与 `inter-op` 线程配置。
- 每组配置重复次数：runner 默认执行 `2` 次 warmup 和 `3` 次计量 batch；构造 `label_operator_actual_dur_us` 与整图真值时，再丢弃最早一个计量 batch，因此最终统计采用剩余 `2` 次计量 batch 的均值。

### 4.1.3 数据集与标注方式

实验数据来自 ORT 导出的 DLRM ONNX 图及其配套的 `op_shapes`、算子 profiling 和整图时间线。单算子数据共包含 195,900 条样本，覆盖来自 `case_7_*`、`case_8_*`、`case_9_*` 和 `case_10_*` 的 9 个具体 case；这些 case 对应不同的 Embedding 表配置、Top MLP 规模以及 Bottom MLP 规模。当前数据集中实际包含的 case 为 `case_7_5_5`、`case_8_1_1`、`case_8_4_4`、`case_9_4_4`、`case_10_1_1`、`case_10_2_1`、`case_10_3_3`、`case_10_4_4` 和 `case_10_4_6`。数据进一步展开为 3,265 个 `combo` 配置，其中每个 `combo` 对应一组输入规模参数，即一个 batch size 与每次 lookup 索引数的组合。相关参数范围如表 4-1 所示。为了让后续精度分析具有结构性解释，本文再按算子机理将样本划分为五类：计算主导类、索引访存类、布局搬移类、轻计算-访存混合类以及视图/元数据类，具体组成见表 4-2。

### 4.1.4 数据划分与评价指标

为避免同一组合配置同时出现在训练集与测试集，本文按 `sample_group=combo` 做 `7:2:1` 划分，实际样本数为 train/val/test = `137,160 / 38,880 / 19,860`。这一随机测试集用于回答模型在分布内配置上的基本精度问题。

单算子层面采用 `MAE`、`MAPE`、`RMSE` 与 `R^2` 评价精度；整图层面除 `MAE`、`MAPE` 外，还统计 `P50/P90` 相对误差，以衡量误差尾部的稳定性。之所以特别关注误差尾部，是因为 branch-parallel 整图预测不仅要求均值误差较低，还要求局部节点偏差不会在同步边界处被系统性放大。需要说明的是，如果仅简单累加节点时延，往往会忽略实际执行中的并行重叠并显著高估整图 makespan；这一点将在 4.4 节通过消融实验进一步验证。

## 4.2 单算子性能建模结果

本节围绕 single-only 设置回答两个问题：单算子模型在随机测试集上是否足够准确；误差是否具有可解释的结构。由于这一版实验不再引入 grouped MLP，对比对象仅保留纯解析基线与统一 single MLP，因此证据链可以更集中地落在“解析代理 + 统一学习器 + 静态聚合”这一主线之上。

### 4.2.1 总体预测精度

我们首先考察随机测试集上的总体精度，因为这是判断单算子模型能否作为整图聚合输入的首要标准。表 4-3 给出了纯解析模型与统一 single MLP 的结果。纯解析模型在其可覆盖测试样本上的 `MAPE` 为 0.2364，而统一 single MLP 在完整测试集上的 `MAPE` 下降至 0.0759，`R^2` 达到 0.9854，说明统一学习器已经能够较稳定地恢复节点时延的主导趋势。

表 4-3 单算子总体预测精度

| 模型 | 样本数 | `MAE/us` | `MAPE` | `RMSE/us` | `R^2` | `P50 APE` | `P90 APE` | `APE > 10%` 比例 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 纯解析模型（组内最佳解析代理） | 13,902 | 54,245.191 | 0.236433 | 153,111.773 | 0.850621 | 0.151241 | 0.574041 | 0.647677 |

如果进一步观察误差分布，single MLP 的 `P50/P90 APE` 分别为 0.0474 和 0.1723，`APE > 10%` 的比例为 0.2377；相比之下，纯解析模型对应比例为 0.6477。也就是说，统一学习器不仅降低了平均误差，也明显压缩了误差尾部。图 4-3 中多数样本分布在 `y=x` 参考线附近，进一步说明该模型已经具备作为后续整图聚合输入的稳定性。本节关注的重点不是把单算子误差压到接近零，而是确认节点级误差已经被控制在整图建模可接受的范围内。

### 4.2.2 分类别误差分析

在总体误差之外，进一步按算子类别拆解可以判断模型是否真正学到了稳定的机理信号，而不是仅在整体均值上“碰巧有效”。表 4-4 与图 4-4 展示了五类算子的误差差异。其中，`view/meta` 与 `layout move` 两类算子最容易预测，其 `MAPE` 分别为 0.0535 和 0.0645；`Gather` 的 `MAPE` 为 0.0743；`light compute-mem` 与 `compute dominant` 的误差相对更高，分别为 0.0972 和 0.1087。

### 4.2.3 典型算子现象分析

为进一步解释上节的类别级结论，图 4-5(a) 至图 4-5(d) 分别展示了四类代表性算子的相对误差与其主导规模特征之间的关系。图 4-5(a) 给出了 `Gather` 的相对误差与索引查找工作量（`feat_lookup_count`）之间的关系。按索引查找工作量（`feat_lookup_count`）的分位区间统计，低规模区间 `1.00×10^0-1.72×10^6` 上的 `MAPE/P90 APE` 分别为 `0.0601/0.1293`，而较高规模区间 `1.82×10^6-2.37×10^6` 和 `2.42×10^6-4.10×10^6` 上分别达到 `0.0774/0.1649` 和 `0.0740/0.1492`，说明随着索引查找工作量（`feat_lookup_count`）增大，随机访存波动更容易放大尾部误差。图 4-5(b) 给出了 `ReduceSum` 的相对误差与归约工作量（`feat_reduction_work_items`）之间的关系。按归约工作量（`feat_reduction_work_items`）的四分位区间统计，其 `MAPE` 由最低工作量区间 `2.62×10^8-6.15×10^8` 上的 `0.0998` 下降到最高工作量区间 `9.98×10^8-1.64×10^9` 上的 `0.0696`，`P50 APE` 由 `0.0778` 下降到 `0.0499`，`P90 APE` 也由 `0.2125` 下降到 `0.1636`。这说明当归约工作量（`feat_reduction_work_items`）足够大时，固定开销和运行时噪声的占比下降，解析代理对归约主导成本的刻画更为有效。图 4-5(c) 给出了 `Transpose` 与 `Concat` 的相对误差随数据搬移字节量（`feat_io_bytes_sum`）变化的情况。按数据搬移字节量（`feat_io_bytes_sum`）的四分位区间统计，若取上下界不重合的有效区间进行比较，其 `MAPE` 由中低规模区间 `4.80×10^1-5.90×10^5` 上的 `0.0666` 上升到最高区间 `1.52×10^7-5.90×10^7` 上的 `0.0878`，`P90 APE` 也由 `0.1342` 上升到 `0.1827`，说明这两类算子的预测偏差主要随数据搬移量（`feat_io_bytes_sum`）扩大而上升。图 4-5(d) 给出了 `Gemm/MatMul` 的相对误差与乘加运算量（`feat_gemm_mac_count`）之间的关系。按乘加运算量（`feat_gemm_mac_count`）的四分位区间统计，其 `MAPE` 由低区间 `8.45×10^5-4.67×10^7` 上的 `0.1431` 下降到高区间 `1.17×10^9-2.62×10^9` 上的 `0.0880`，`P90 APE` 也由 `0.2966` 下降到 `0.1678`，反映出小维度下微核利用率不足会更明显地放大误差。

这些现象表明，模型误差并非完全无结构的黑盒偏差，而是能够被硬件与 kernel 行为解释的残差。这比单纯报告总体 `MAPE` 更有分析价值，因为它说明第三章提出的特征设计确实捕获了决定节点时延的主导因素，而剩余误差更多来自随机访存、小张量固定开销或低利用率计算等动态效应。

## 4.3 整图静态聚合结果

单算子精度只是第一步。对 DLRM 这类 branch-parallel 推理图而言，更关键的问题在于：在多个 embedding 分支、bottom 与 tail 相互重叠的条件下，节点级预测能否进一步恢复整图关键路径与总体时延。本节围绕这一问题验证第三章 3.3 中提出的静态流水线聚合模型。

### 4.3.1 整体整图精度

整图总体精度是评估两级建模方案有效性的关键指标。表 4-5 汇总了整图预测结果。其中，`overall` 表示全部 331 个完整图配置上的总体统计结果，`small`、`medium` 和 `large` 则分别表示按 `batch size` 划分的小、中、大三档区间，对应 `batch_size ≤ 1280`、`1280 < batch_size ≤ 1792` 和 `batch_size > 1792` 的配置集合。考虑到 `R^2` 更适合用于刻画整体样本上的拟合程度，而分桶后的区间内方差显著收缩，表中仅在 `overall` 行报告 `R^2`，其余分组主要比较相对误差统计。在 331 个完整图配置上，静态流水线模型的 `MAPE` 为 0.0647，`R^2` 为 0.9931，`P50/P90` 相对误差分别为 0.0509 和 0.1261。由此可见，节点级预测误差在整图聚合后未出现显著累积，模型能够较准确地恢复整图 `makespan`，并将尾部误差控制在相对稳定的范围内。图 4-11 中预测值与真实值整体沿参考线分布，与表 4-5 的统计结果相一致。上述结果表明，在本组 single-only 实验中，基于节点级时延预测与静态流水线聚合的两级建模方案能够有效刻画整图执行时间。

### 4.3.2 不同 batch size 下的稳定性

在总体精度之外，还需要确认模型是否只在局部规模上有效。图 4-12 按 batch size 给出了整图误差分布。整体来看，各个 batch size 上的 `MAPE` 大致落在 `0.03-0.10` 区间内，没有出现随 batch 增长而持续恶化的趋势。即便在误差相对较高的 `batch_size=1440` 处，其 `MAPE` 也约为 0.1000，仍处于可接受范围。

这一结果表明，静态流水线模型并非仅在少数局部规模上有效，而是能够在不同工作集大小下保持较平滑的误差曲线。考虑到 DLRM 中 embedding lookup、分支归约和 top MLP 的张量规模都会随 batch size 改变，这种稳定性是方法成立的重要前提。

这一结果表明，第三章用于刻画 branch 槽位竞争关系的静态近似具有良好的有效性。该近似的目标并非逐事件复现真实运行时调度过程，而是从结构层面捕获影响整图性能的主导因素。结合图 4-13 所示结果可以认为，该建模方式已经能够较好反映并行度变化对整图执行时间的主要影响。

## 4.4 消融实验与误差分析

前两节给出了单算子建模与整图聚合的主要结果，本节进一步通过消融实验分析这些结果的来源。为识别节点级预测能力与整图聚合机制对最终精度的相对贡献，本文采用逐步引入组件的方式，比较 `Analytical + simple add`、`Analytical + pipeline`、`Analytical + single MLP + simple add` 和 `Analytical + single MLP + pipeline` 四个变体。该实验设计旨在区分整图精度改善主要来源于节点级预测误差的降低，还是来源于静态流水线聚合对执行结构的更准确刻画；同时，也为后续误差尾部样本的来源分析提供参照。

### 4.4.1 关键组件的作用

图 4-16 给出了四个变体在整图相对误差上的累积分布。可以看到，两条采用 `pipeline` 聚合的曲线整体明显左移于对应的 `simple add` 版本，表明在相同节点级预测条件下，显式建模分支重叠与同步边界能够显著压缩整图误差分布。与此同时，`Analytical + single MLP + pipeline` 的曲线进一步左移于 `Analytical + pipeline`，说明更准确的节点级预测仍然能够在静态聚合框架内继续转化为整图精度收益。

图 4-17 进一步给出了各变体的平均相对误差与 `APE > 10%` 比例。对于纯解析模型，若整图仅采用 `simple add`，其整图 `MAPE` 高达 2.0450，`APE > 10%` 比例为 0.8912；当聚合方式改为 `pipeline` 后，两项指标分别下降至 0.1389 和 0.6616。对于引入统一 `single MLP` 的版本，`simple add` 下的整图 `MAPE` 仍为 1.8814，`APE > 10%` 比例为 0.6918，而切换到 `pipeline` 后则进一步下降至 0.0647 和 0.1873。该结果表明，静态流水线聚合是控制整图平均误差和尾部误差的关键因素，而更高质量的节点级预测则在此基础上进一步压缩误差水平。

图 4-18 展示了不同 `inter_threads` 条件下各消融变体的整图 `MAPE` 变化。结果表明，在不同分支并行度配置下，`pipeline` 版本始终优于对应的 `simple add` 版本，而 `Analytical + single MLP + pipeline` 在各并行度条件下均保持最低误差水平。这说明整图精度的提升并非局限于个别并行度配置，而是能够在不同 branch 槽位规模下稳定复现。综合图 4-16 至图 4-18 可以认为，节点级学习器负责降低局部预测偏差，而静态流水线聚合负责将节点级结果组织为符合真实执行结构的整图估计，两者共同构成当前 single-only 设置下精度提升的主要来源。

### 4.4.2 误差来源分析

如果将 `APE > 10%` 的样本视为当前方法的误差尾部，则表 4-7 与图 4-19 说明这些尾部样本并非平均分布在所有场景中，而是集中在几类特定模式。第一类是大表随机访存 `Gather`，其误差来源于内存访问时延的天然波动；第二类是极小张量的视图/元数据算子，此时框架调度与 bookkeeping 开销占比较高，使得时延对形状特征更加敏感；第三类是小维度 `Gemm/MatMul`，在低利用率条件下其真实执行代价偏离了饱和计算近似；第四类是同步敏感的整图配置，局部偏差会在 tail barrier 处被放大。

## 4.5 本章小结

本章在 195,900 条单算子样本和 331 个完整图配置上验证了第三章提出的两级建模框架。首先，在随机测试集上，统一 single MLP 的单算子 `MAPE` 为 0.0759，显著优于纯解析基线的 0.2364，表明静态特征已经能够为节点级时延提供稳定预测。进一步将节点级预测接入静态流水线后，整图预测 `MAPE` 达到 0.0647，`P90` 相对误差为 0.1261，说明节点误差并未在整图层面失控放大。

消融实验进一步明确了本章结论所依赖的核心因素。若忽略并行重叠，仅做 simple add，则整图误差会出现数量级恶化；而当节点级学习器与静态流水线聚合同步存在时，整图精度达到最佳。与此同时，误差来源分析表明，当前尾部误差主要集中在随机访存、小张量固定开销、小规模矩阵计算以及同步敏感配置等场景。总体而言，第四章的实验结果在随机测试、整图聚合与组件消融三个层面上形成了相互一致的证据链，有力支撑了第三章提出的方法设计，并为第五章的进一步讨论提供了实验基础。
